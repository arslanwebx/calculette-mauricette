---

# 1. PURPOSE

This document is the mandatory publishing workflow for every indexable page.

Read `CODEX.md` first.

This playbook controls:

- page intent;
- keyword ownership;
- cannibalization prevention;
- on-page SEO;
- internal linking;
- bidirectional linking;
- metadata;
- indexability;
- sitemap handling;
- post-publish QA.

A page is **not finished** when the new file is created.

It is finished only when it is integrated professionally into the whole website.

---

# 2. CORE RULE

**One search intent = one primary canonical URL.**

Before publishing any new page:

1. inspect the repository;
2. identify exact intent;
3. identify closest existing page;
4. confirm no cannibalization;
5. identify the parent calculator/pillar;
6. identify outgoing links;
7. identify incoming-link opportunities from existing pages;
8. implement both directions where useful;
9. check canonical/indexability/sitemap;
10. run build and broken-link QA.

---

# 3. MANDATORY BIDIRECTIONAL INTERNAL LINKING

Every important new page must participate in two-way internal linking.

## New page → existing pages

Link naturally to relevant:

- parent calculator;
- pillar;
- supporting guide;
- related tool;
- reference resource.

## Existing pages → new page

Search existing repository content for strong contextual opportunities.

Update the best relevant pages so they link back to the new page.

Do not rely only on:

- footer;
- header;
- generic related-post blocks;
- category cards.

Contextual body links are preferred.

---

# 4. INTERNAL LINKING OBJECTIVES

Links should:

1. help users;
2. clarify topic relationships;
3. distribute internal authority;
4. reinforce hierarchy;
5. prevent orphan pages;
6. help new URLs get discovered;
7. strengthen topical authority;
8. reduce cannibalization.

Do not use internal linking as keyword stuffing.

# 8. DO NOT CREATE PAGES FOR TRIVIAL VARIANTS

Bad:

```text
/calculette-mauricette/
/calculatrice-mauricette/
```

Bad unless intents are truly different:

```text
/calcul-heures-travail/
/calcul-des-heures-de-travail/
/calculer-heures-travail/
```

Lexical variants belong inside one authoritative page.

---

# 9. TOOL INTENT VS GUIDE INTENT

Separate URLs may exist when intent differs.

Example:

```text
/calcul-heures-travail/
```

= user wants a calculator.

```text
/comment-calculer-heures-travail/
```

= user wants methodology/explanation.

Make that difference obvious in:

- title;
- H1;
- intro;
- page layout;
- functionality;
- links.

---

# 10. INCOMING LINK AUDIT

For every important new page, inspect existing pages and identify approximately **2–5 strong contextual incoming-link opportunities** where they genuinely exist.

This is not a rigid quota.

Priority:

1. parent pillar;
2. closely related high-value guide;
3. related calculator;
4. supporting article;
5. relevant reference asset;
6. homepage only when strategically justified.

---

# 11. CONTEXTUAL LINK EXAMPLE

Weak:

> Pour une semaine complète, additionnez chaque journée. [En savoir plus]

Better:

> Pour une semaine complète, utilisez notre [calculateur d'heures hebdomadaires](/calcul-heures-semaine/) afin d'additionner automatiquement chaque journée.

The link should be useful even without SEO.

---

# 12. OUTGOING LINK STANDARD

A substantial article should normally include:

- parent calculator/pillar;
- 1–3 closely related pages;
- a deeper resource where useful.

Do not force excessive linking.

---

# 13. ANCHOR TEXT

Good:

- calculer vos heures supplémentaires;
- calcul des heures de travail;
- convertir les minutes en centièmes;
- tableau minutes en centièmes;
- calculer une semaine de travail;
- comprendre les 151,67 heures mensuelles.

Avoid:

- cliquez ici;
- en savoir plus;
- cette page;
- repeated exact-match anchors.

Use natural variation.

---

# 14. LINK PLACEMENT PRIORITY

Prefer:

1. contextual body link;
2. useful inline callout;
3. relevant table/resource link;
4. curated related-content block;
5. navigation/footer.

Footer links alone are not enough.

---

# 15. FIRST RELEVANT MENTION

When genuinely useful, link the first natural mention of a related important topic.

Do not link every repetition.

---

# 16. INTERNAL LINK VOLUME

General guideline only:

- short article: 3–6 useful links;
- medium article: 5–10;
- long guide: 7–15.

These are not quotas.

Use fewer if fewer are useful.

---

# 17. ORPHAN PAGE PREVENTION

Every valuable page should have:

- at least one contextual incoming link;
- logical hierarchy placement;
- sitemap inclusion.

Important pages should have multiple strong incoming links.

---

# 18. CLICK DEPTH

Strategic pages should generally be reachable within 1–2 meaningful clicks from the homepage.

Do not bury important pages.

# 20. ON-PAGE SEO REQUIREMENTS

Every indexable page should have:

- unique title;
- unique meta description;
- one meaningful H1;
- logical H2/H3;
- canonical URL;
- crawlable rendered HTML;
- primary keyword naturally used;
- useful related concepts;
- contextual internal links;
- authoritative sources where needed;
- no accidental noindex;
- sitemap inclusion;
- mobile-friendly rendering.

---

# 21. TITLE TAG STANDARD

Good:

```text
151,67 heures par mois : calcul et explication
```

Bad:

```text
151,67 Heures Calcul 35h Heures Mois Temps Travail France
```

Do not add a year merely to fake freshness.

---

# 22. OPENING STANDARD

Answer the main question in the first 2–4 sentences where practical.

Avoid filler:

> Dans le monde du travail moderne...

Start with the answer.

---

# 23. KEYWORD USE

Use primary keyword naturally in:

- title;
- H1;
- introduction;
- relevant heading where useful;
- body.

No keyword-density target.

Do not mechanically repeat exact phrases.

---

# 24. SEMANTIC COVERAGE

Cover related concepts only when they help answer the query.

Do not turn the article into a keyword list.

---

# 25. INFORMATION GAIN

Every important page should contain at least one useful advantage such as:

- calculator;
- worked example;
- formula;
- conversion table;
- downloadable spreadsheet;
- printable sheet;
- edge-case explanation;
- comparison;
- common mistake demonstration.

Do not publish generic paraphrases.

---

# 26. PAGE TYPE RULES

## Calculator page

Should generally include:

1. tool immediately;
2. concise explanation;
3. worked example;
4. formula/method;
5. edge cases;
6. useful links;
7. FAQ only if helpful.

## Informational guide

Should include:

1. direct answer;
2. explanation;
3. examples;
4. official verification where needed;
5. calculator links;
6. supporting links.

## Reference asset

Should include:

1. usable table/download;
2. concise explanation;
3. method;
4. related tool links;
5. printable/download version where useful.

---

# 27. RELATED CONTENT

Related-content blocks must be curated semantically.

Do not show random recent posts.

---

# 28. BREADCRUMBS

Use breadcrumbs on deeper pages when useful.

Example:

```text
Accueil > Temps de travail > 151,67 heures par mois
```

They must reflect real hierarchy and use crawlable links.

---

# 29. EXTERNAL SOURCES

For French legal/payroll content, prioritize:

1. Legifrance;
2. Service-Public.fr;
3. Ministère du Travail;
4. URSSAF;
5. other authoritative official sources.

Do not cite competitors as legal authorities.

---

# 30. LEGAL CONTENT LINKING

Use calculators as practical aids, not individualized legal determinations.

Good:

> Pour vérifier votre total, utilisez le [calculateur d'heures de travail](/calcul-heures-travail/).

Avoid implying the tool can definitively determine legal entitlements unless it truly can.

---

# 31. EXISTING-PAGE UPDATE REQUIREMENT

When publishing a new page:

```text
1. Create new page.
2. Search repository for relevant mentions.
3. Identify strongest existing pages.
4. Add contextual links from those pages to new page.
5. Add relevant links from new page back to existing content.
6. Check anchor variation.
7. Check broken links.
8. Ensure sitemap update.
9. Run production build.
```

Mandatory.

# 33. CONTENT REFRESH LINK AUDIT

When updating an old article:

- remove broken links;
- replace outdated targets;
- add newer useful resources;
- remove unhelpful links;
- keep anchors natural.

---

# 34. NO BLIND AUTO-LINKING

Never replace every occurrence of a keyword with a link.

Choose links editorially.

---

# 35. NO SELF-LINKS

Do not link a page to itself with its main keyword.

---

# 36. NO REDIRECTED INTERNAL LINKS

Point internal links directly to final canonical URLs.

If a slug changes:

- update internal links;
- add proper redirect;
- update sitemap;
- avoid chains.

---

# 37. URL CONSISTENCY

Use the site's canonical trailing-slash style consistently.

For internal body links, prefer relative paths such as:

```text
/calcul-heures-travail/
```

---

# 38. ZERO BROKEN INTERNAL LINKS

Never publish links to routes that do not exist.

Do not create SEO-facing 404s.

# 40. CANNIBALIZATION CLEANUP

If multiple pages rank for the same intent:

1. compare performance;
2. choose stronger page;
3. merge unique useful content;
4. redirect weaker URL if removed;
5. update internal links;
6. update sitemap;
7. verify canonical.

Do not preserve duplicate pages just to keep page count.
